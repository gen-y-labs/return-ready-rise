RETURN READY — NATIONWIDE JOB DATA SOURCES API ENDPOINTS, FEEDS, AND
OFFICIAL DOCUMENTATION Prepared: November 14, 2026

IMPORTANT NOTES - There is no single unrestricted public API that
provides every job opening in the United States. - An accessible public
career page does not automatically mean its data may be harvested,
stored, or republished. - Confirm current documentation, authentication,
pricing, rate limits, attribution, and redistribution terms before
production use. - Endpoints containing {PLACEHOLDER} values must be
populated with the employer’s board token, company slug, or other
identifier. - Treat provider APIs, employer-specific ATS board feeds,
partner-only feeds, and ordinary job-search websites as different source
types. - Do not bypass authentication, anti-bot controls, or site
restrictions.

============================================================ 1.
GOVERNMENT AND PUBLIC-SECTOR SOURCES
============================================================

1.1 USAJOBS — U.S. federal government jobs Official developer portal:
https://developer.usajobs.gov/ API documentation / getting started:
https://developer.usajobs.gov/API-Reference API access: - API
credentials are required. - Use the current official documentation for
the required headers, query parameters, and pagination. - Federal
vacancy search endpoint is documented in the USAJOBS API reference; do
not hard-code an unverified endpoint pattern. Coverage: - Federal
government vacancies. Notes: - Not a feed for all state, county, or
municipal jobs.

1.2 CareerOneStop — U.S. Department of Labor-sponsored career services
API explorer: https://api.careeronestop.org/api-explorer/ API portal:
https://www.careeronestop.org/Developers/WebAPI/web-api.aspx Access: -
API key / user authorization required. Coverage: - Job search and career
information, depending on the specific API operation. Notes: - Review
the API explorer for the current operation paths and parameters.

1.3 National Labor Exchange (NLx) Data access:
https://nlxresearchhub.org/data-access Main site: https://www.usnlx.com/
Access: - Data access may require approval, a data-use agreement, or a
partnership. Coverage: - Broad U.S. job-posting data, subject to
approved access. Notes: - Do not assume unrestricted public API access.

1.4 Utah Department of Workforce Services / Employ Utah Main site:
https://jobs.utah.gov/ Utah job search:
https://jobs.utah.gov/jsp/utjobs/utjobs.jsp Employment information
dashboard: https://jobs.utah.gov/wi/empinfo/index.html Access: - Public
job-search website and labor-market information. - No generally
available public job-search API is confirmed here. Recommended next
step: - Contact Utah DWS and ask about authorized UWORKS / Employ Utah
API access, partner feeds, data-sharing agreements, and redistribution
rights.

1.5 State, county, and municipal job portals There is no single standard
endpoint for all state and local government vacancies. Discovery sources
/ examples: - State workforce agency job banks: locate each state’s
official workforce agency and job-bank documentation. - County and city
government career pages: use each jurisdiction’s official careers
portal. - GovernmentJobs / NEOGOV: https://www.governmentjobs.com/
Employer-specific career pages and integrations vary; confirm API or
feed access with the provider/employer. - California state jobs:
https://www.calcareers.ca.gov/ Notes: - A public search page is not
proof of an open API. - Build a source registry by state and
jurisdiction and record the official access method for each.

1.6 U.S. Department of Labor data DOL Data Portal: https://data.dol.gov/
Notes: - Useful for labor-market and related public datasets. - It is
not a universal real-time vacancy API.

1.7 Other public-sector categories to onboard individually - Public
school districts and state education departments. - Public universities
and community colleges. - State and local public healthcare systems. -
Transit authorities, utilities, courts, and special districts. - Federal
agencies with agency-specific career sites. For each, identify the
official careers page, ATS vendor, documented API/feed, and
redistribution terms.

============================================================ 2.
COMMERCIAL JOB-SEARCH AGGREGATOR APIs

2.1 Adzuna Developer portal: https://developer.adzuna.com/ Typical
documented search URL pattern:
https://api.adzuna.com/v1/api/jobs/{COUNTRY}/search/{PAGE} Example
country code for U.S. searches: us Typical query parameters include
app_id, app_key, results_per_page, what, where, and related filters.
Authentication: - App ID and API key. Notes: - Verify current plan,
quota, fields, and redistribution terms in the developer portal.

2.2 Jooble API information: https://jooble.org/api/about Typical
endpoint pattern: https://jooble.org/api/{API_KEY} Method: - POST with
JSON search criteria, as documented by Jooble. Authentication: - API
key. Notes: - Confirm current request schema, quotas, and permitted
display/redistribution.

2.3 Talroo API documentation: https://docs.talroo.com/api/search
Access: - Confirm account / partner access and current authentication
requirements. Notes: - Commercial product; check pricing and permitted
use with Talroo.

2.4 JobsPiper Documentation: https://docs.jobspipe.dev/ Access: - Review
current documentation for endpoint paths, authentication, and commercial
terms. Notes: - Validate provider coverage and data licensing before
integrating.

2.5 Other vendor leads — verify before implementation The following

============================================================ 3. EMPLOYER
ATS PUBLIC JOB-BOARD ENDPOINTS
============================================================

These are generally employer-specific public posting feeds. They do not
provide a universal search API across every employer using that ATS. The
employer’s board identifier / token is required.

3.1 Greenhouse Official Job Board API documentation:
https://developers.greenhouse.io/job-board.html Public jobs endpoint
pattern: GET
https://boards-api.greenhouse.io/v1/boards/{BOARD_TOKEN}/jobs Include
job content: GET
https://boards-api.greenhouse.io/v1/boards/{BOARD_TOKEN}/jobs?content=true
Identifier: - Employer’s Greenhouse board token. Notes: - Use only for
employers whose public Greenhouse board is known and accessible. - Check
Greenhouse documentation and applicable terms for permitted use.

3.2 Lever Official postings API reference:
https://github.com/lever/postings-api Public postings endpoint pattern:
GET https://api.lever.co/v0/postings/{COMPANY} JSON mode: GET
https://api.lever.co/v0/postings/{COMPANY}?mode=json Identifier: - Lever
employer/company slug. Notes: - Employer-specific postings; verify
current documentation and terms.

3.3 Ashby Official Public Job Posting API documentation:
https://developers.ashbyhq.com/docs/public-job-posting-api Public
endpoint pattern: GET
https://api.ashbyhq.com/posting-api/job-board/{JOB_BOARD_NAME}
Compensation option shown in provider documentation: GET
https://api.ashbyhq.com/posting-api/job-board/{JOB_BOARD_NAME}?includeCompensation=true
Identifier: - Ashby job board name. Notes: - Confirm currently supported
query parameters and permitted use in official docs.

3.4 SmartRecruiters Developer portal: https://dev.smartrecruiters.com/
Public postings endpoint pattern: GET
https://api.smartrecruiters.com/v1/companies/{COMPANY_IDENTIFIER}/postings
Identifier: - SmartRecruiters company identifier. Notes: - Check current
API version, pagination, authentication, and terms.

============================================================ 7. SOURCE
REGISTRY FIELDS TO TRACK
============================================================

For every source, store: - source_id - source_name - source_category
(government, aggregator, ATS, remote, nonprofit, etc.) -
sector_coverage - geographic_coverage - access_method (REST, JSON, XML,
RSS, partner feed, manual link) - endpoint_template -
authentication_required - approval_or_partnership_required -
pricing_or_free_tier - rate_limit - pagination_method -
refresh_frequency_hours - available_fields - attribution_required -
redistribution_approved - terms_url - permission_status (confirmed,
pending, restricted, unclear) - integration_status (active, testing,
pending, inactive, failed) - last_verified_at - notes

============================================================ 8.
NORMALIZED JOB RECORD FIELDS
============================================================

Recommended normalized fields: - job_id - source_id - source_job_id -
job_title - employer_name - employer_sector - industry -
job_description - country - state - county - city - postal_code -
work_mode (remote, hybrid, onsite) - employment_type (full-time,
part-time, contract, temporary, seasonal, internship, apprenticeship,
returnship) - salary_min - salary_max - salary_currency -
salary_frequency - experience_level - education_requirements - skills -
schedule - flexibility_details - accessibility_details -
career_reentry_or_training - posted_date - closing_date -
application_url - source_url - last_seen_at - last_synced_at -
active_status

For caregiver-focused matching, derive additional tags after
ingestion: - flexible_hours - predictable_schedule -
part_time_possible - remote_possible - transferable_skills -
career_break_friendly - returnship - entry_level - training_provided -
childcare_schedule_compatible
